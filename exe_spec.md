# Спецификация приложения «Сладкий городок»

## Что приложение должно точно уметь

### 1. Два направления
- **Бухгалтерия / производство**
  - Карточка товара (фото, состав, рецептура)
  - Расчёт себестоимости (ингредиенты, упаковка, труд, накладные)
  - Нормы расхода материалов на единицу товара
- **Аналитика**
  - Маржинальность по товарам/категориям
  - Динамика продаж, ABC/XYZ анализ
  - Сводные отчёты для управленческих решений

### 2. Жизненный цикл заказа
- Стадии: создан → подтверждён → в производстве → готов → отгружен/доставлен → оплачен → закрыт
- История изменений статуса, ответственный на каждом этапе
- Привязка заказа к складским списаниям и себестоимости

### 3. Складской учёт
- Остатки по складам (несколько точек хранения)
- Приход/расход/перемещение между складами
- Инвентаризация и история движения товара

### 4. Сотрудники и оплата труда
- Учёт рабочего времени (смены, часы)
- Расчёт зарплаты (сдельная/окладная/премии)
- Итоги по сотруднику: выработка, эффективность, история выплат

### 5. Импорт данных из внешних источников
- 1С (старая версия) — выгрузка/парсинг
- 1С (новая версия) — выгрузка/парсинг
- Банк — выписки, сверка платежей
- Маппинг полей и дедупликация при импорте

### 6. API интеграция
- REST API для внешних систем (сайт, маркетплейсы, мобильное приложение)
- Вебхуки на изменение статуса заказа/остатков
- Авторизация по токену, лимиты запросов

### 7. Ручной ввод данных
- Добавление/редактирование товаров, заказов, остатков, сотрудников прямо в приложении
- Валидация вводимых данных, права доступа по ролям

### 8. Кроссплатформенность
- Веб-доступ (браузер) как основа
- Адаптивная вёрстка: десктоп (Mac/Windows) и мобильные устройства (Android/iOS)
- Возможен PWA или нативная обёртка для офлайн-режима на складе
